# 用单一 Agent Interface 和计划摘要约束跨机变更

CCS 是本机 Agent、CLI 或脚本与从机之间的桥梁，不应要求调用方依赖 Python 内部类，也不应把上层科研判断混入远端执行层。主机因此提供单一版本化 JSON Request/Result Interface，并由 `ccsctl request --file` 暴露稳定进程边界。

每个请求显式声明调用者、动作、载荷和 `dry_run`。只读动作可以直接执行；变更动作必须先以 `dry_run: true` 取得规范化计划的 SHA-256，再以完全相同的请求身份、动作和载荷提交 `confirm_plan_sha256`。摘要不包含 `dry_run` 和确认字段，因此计划与执行可稳定比对；任何输入变化都会产生不同摘要。预演只协商能力和验证输入，不调用目标动作。

新变更要求从机能力兼容，防止旧端静默忽略安全语义。`run.cancel` 是止损例外：只要旧从机可达且仍支持既有取消命令，即使未声明新接口也允许经摘要确认后停止。只读操作在滚动升级期间同样允许访问旧从机。

网关审计只保存调用者、动作、分类、计划摘要、结果状态和错误码，不保存请求载荷或响应正文。模型代码、命令参数、数据路径和日志内容不会复制进审计库。科研规划、实验选择、结果解释和论文写作继续属于上层 Agent 工作流，不属于 CCS Interface。
