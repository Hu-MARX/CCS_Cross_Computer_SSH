# 新建 Run 前协商从机协议和能力

CCS 客户端与从机可能独立升级，单看软件版本字符串不能判断某项行为是否存在，也不能把旧从机不认识新参数误报成网络故障。因此，从机在既有 `health` 响应中嵌入版本化接口声明，并通过独立 `capabilities` 命令返回同一声明；客户端先检查协议主版本，再逐项比较本次操作所需能力的最低版本。

缺少接口声明的可达从机标记为 `legacy`，协议主版本不同或能力不足标记为 `incompatible`，SSH 失败仍走原连接错误。只读观测在滚动升级期间保持可用；新建 Run 必须先通过能力协商，旧版或不兼容从机在远端提交发生前被拒绝。协议次版本允许增加向后兼容字段，能力版本负责表达单项语义升级，不按软件语义版本猜测功能。

该决定为每次新建 Run 增加一次健康检查，但消除了新客户端向旧从机静默发送不受支持参数的风险。部署顺序应先等待既有长任务终态，再升级从机；升级前看板会显示旧版接口，现有 Run 不受影响。
