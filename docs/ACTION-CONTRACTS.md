# CCS Action Contracts

Generated by `python scripts/render-action-contracts.py` from the packaged canonical resource `src/ccs/resources/action-contracts.json`. Change the resource and regenerate; CLI, gateway validation, SDK and MCP contract queries use this same source.

## Offline access

```console
ccsctl describe
ccsctl describe --action run.submit
ccsctl describe --action workspace.execute --workspace-action stage
ccsctl describe --schema request
```

`gateway.describe` is also a local-only read action with optional `action` and `workspace_action` payload fields. It works without host configuration, databases, SSH or network. SDK callers can use `CCSClient.describe()`; MCP callers can use `ccs_read(action="gateway.describe", payload={"action":"run.submit"})`.

Input and output schemas returned by describe are self-contained JSON Schema 2020-12 documents with local references. The three published schemas are generated by `ccs.contracts.request_schema()`, `result_schema()` and `experiment_spec_schema()`; runtime schema lookup needs only the installed package resource.

## Compatibility and errors

- **protocol_version**: 1
- **previously_valid_requests**: Existing documented requests and default worker behavior remain supported.
- **strict_validation**: Unknown action/workspace fields, missing required fields and illegal JSON types now fail locally with field_errors before remote routing.
- **metadata_extensions**: ExperimentSpec project/runtime/resources/outputs/evaluation/success/automation and command metadata remain extensible.
- **dynamic_constraints**: Worker existence, admission, capabilities, filesystem confinement and exact staged hashes are evaluated at execution time.
- **bounded_pages**: New page options require page capabilities. Legacy lists remain supported with bounded transport errors on oversized responses.

All documented valid requests keep their existing meanings. Unknown fields on action payloads and workspace requests, missing required fields and illegal types now fail before compatibility checks or remote calls. Booleans are not accepted as integers. Unknown fields that were previously ignored no longer silently succeed; use the selected contract to remove them. ExperimentSpec metadata scopes remain extensible.

Contract failures include `code`, `message`, `retryable=false`, `execution_state="not_sent"` and `field_errors` with exact paths, stable field codes and descriptions. Values are omitted from error descriptions.

```json
{
  "code": "INVALID_REQUEST",
  "message": "payload violates its action contract",
  "retryable": false,
  "execution_state": "not_sent",
  "field_errors": [
    {
      "path": "payload.spec.command.argv",
      "code": "required",
      "message": "required field is missing"
    }
  ]
}
```

Mutation classification still requires the existing dry-run and exact gateway confirmation. The workspace `plan_sha256`/`applied_sha256` fields identify a staged worker change and are separate from `confirm_plan_sha256` in the gateway request envelope. A matching hash is not authentication or proof of user approval.

Output schemas describe `result` after execution. A dry-run result may be null or a worker plan. Worker diagnostics and snapshots have optional fields because legacy/Fake workers and new workers expose different facts; absence does not imply zero or healthy state. Metadata extension fields may be added by adapters.

- Paged reads require run.events.page>=1; after_seq is the last delivered event sequence.
